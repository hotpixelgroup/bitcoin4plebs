# Learning accuracy and interaction review

Scope: `bitcoin4plebs` source and `lightning4plebs` publishing workflow, inspected 2026-10-15. Source baseline: `6fcd69c7d2723ff8e30319ea23503b015416be6c`. Implementation branch: `fix/site-isolation-learning-labs`. No merge or deployment is authorized. The publishing repository needs no source change: it builds this source's `main` with `VITE_SITE=lightning`.

## First batch acceptance criteria

- Sequential Nx builds, including cache hits and a base-path-only change, produce the requested brand, asset paths, fallback HTML and PWA manifest.
- Missed quizzes use independent site keys. Each site imports only matching legacy questions once; legacy data remains intact. Retirement is not undone by later migration. Malformed/denied storage does not crash learning.
- Three peers endorsing an invalid mint cannot make it valid.
- UTXO construction supports changing payment and fee, prediction, insufficient-input failure, pending/confirmed states and conservation. For 0.50 + 0.30 inputs, 0.60 payment and 0.0001 fee, change is 0.1999 BTC. Failed attempts do not change confirmed state.
- Channel payments preserve total value; closing never increments payment count. Delayed output spending requires clock progression and explicit confirmation. A penalty requires an active observer and explicit timely confirmation. Funding, commitment and penalty/sweep are counted separately.
- Route attempts can fail for directional liquidity or an offline fixture, then retry. Failure delivers/charges zero; success delivers the exact invoice and sender funds fees on top. The 10,199-msat vector remains exact.
- Enhanced controls work by keyboard, explanatory state is text-accessible, and critical pages fit 320px. New state transitions have no automatic animation.

## Sources and boundaries

Pinned source snapshots remain unchanged: Bitcoin Core `18c05d93016b28a9afd4c716dfe00b6e0accb30b`, BIPs `8c369ac8e60629ac6c032ffe21bb5ec5b35213d7`, BOLTs `94eb038c42e664dd7862faeec6508ccd25f63ff8`, LND `29257ecc8892af0c882fa627b66a556190c84fd9`. Fetched locally to run excerpt and official-vector checks. Claims about current status are dated separately from those snapshots.

Primary references: [BIP39](https://bips.dev/39/), [BIP32](https://bips.dev/32/), [BIP340](https://bips.dev/340/), [BIP341](https://bips.dev/341/), [BIP173](https://bips.dev/173/), [BIP350](https://bips.dev/350/), [Core 28](https://bitcoincore.org/en/releases/28.0/), [BIP110 current text](https://github.com/bitcoin/bips/blob/master/bip-0110.mediawiki), and pinned BOLT #2/#3/#4/#5/#7/#11.

These are educational simulations with no funds, real wallet keys, production signing or transaction submission. The channel is a simplified legacy-style two-party channel without pending HTLCs, reserves, dust, anchors or fees. Button actions labelled “confirm” assume inclusion, not transaction construction or actual mining. The 144-block delay and route liquidity fixtures are illustrative. The decoder still does not verify ECDSA, full mandatory/duplicate-feature rules, expiry/payability or intended-recipient identity. Sphinx is not a full TLV or production packet validator. Compact-target helpers do not enforce network-specific expected difficulty or powLimit.

## Explicit remaining audit scope and follow-on order

This batch is not a claim that every sentence or economic assertion across both sites is now correct. The final audit supplied a wider backlog; the following remain deliberate follow-on work, not verified fixes:

1. **Protocol/evidence reconciliation:** accept complete `gettxoutsetinfo` JSON with matching height/bestblock and optional coinstats-index fields; validate source/time for external signet and mempool observations; distinguish a single explorer's 404 from network absence. Add node-bootstrap stale/withheld-chain and assumevalid/genesis nuances throughout Quest 9. Acceptance: mismatched snapshots cannot receive a successful audit verdict.
2. **Transactions, fees and policy:** coherent FeeAuction arrival trace and package-aware selection; complete replacement-policy examples; context-free `RunTheCheck` versus full acceptance; exact historic CVE exploit and “no known exploitation” phrasing. Datacarriersize is OP_RETURN relay policy, not a general witness-size cap. Acceptance: one event trace drives both histogram and estimator; full validity never inferred from context-free checks or fee rate.
3. **Chain and attacks:** actual 80-byte serialized-header mining exercise, pure reusable chain-state transitions, attacker mining during merchant wait, explicit tie resolution, and model assumptions for work/energy/economics. The present fixed-deficit experiment is narrower. Acceptance: byte serialization matches a known header vector and minority-attacker outcomes are not described as impossible.
4. **Privacy and custody:** more ambiguous and collaborative-spend fixtures, extracted pure inference tests, descriptor/cosigner recovery examples, current channel-state recovery and watchtower limitations. Acceptance: ground truth is never used as an inference feature or grading oracle for its own guesses; hypotheses expose false positives.
5. **Curriculum sweep:** remaining broad economic/energy claims, genesis headline intent/difficulty context, finite signet subsidy/faucet availability, precise UTXO spending conditions beyond one-key analogies, selected-upgrade timeline versus all consensus changes, and old short-form copy still needing independent review. Verify current policy metadata and proposal cross-links. Acceptance: each changing factual claim is dated/sourced, and no recap overrides a qualified lesson with an absolute.
6. **Learning design:** reusable pure reducers for all expanded labs, explicit funding-ready negotiation and HTLC reservations, route-balances before/after, prediction scoring, richer reorg network propagation and HTLC claim/timeout races. Existing lab state is local and deterministic except the now explicitly scoped hashing demos. Avoid building a new framework before these scenarios need one.
