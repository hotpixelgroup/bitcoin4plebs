# Learning accuracy and interaction review

Scope: `bitcoin4plebs` source and `lightning4plebs` publishing workflow, inspected 2026-10-15. Source baseline: `6fcd69c7d2723ff8e30319ea23503b015416be6c`. Implementation branch: `fix/site-isolation-learning-labs`. No merge or deployment is authorized. The publishing repository needs no source change: it builds this source's `main` with `VITE_SITE=lightning`.

## First batch acceptance criteria

- Sequential Nx builds, including cache hits and a base-path-only change, produce the requested brand, asset paths, fallback HTML and PWA manifest.
- Missed quizzes use independent site keys. Each site imports only matching legacy questions once; legacy data remains intact. Retirement is not undone by later migration. Malformed/denied storage does not crash learning.
- Three peers endorsing an invalid mint cannot make it valid.
- UTXO construction supports changing payment and fee, prediction, insufficient-input failure, pending/confirmed states and conservation. For 0.50 + 0.30 inputs, 0.60 payment and 0.0001 fee, change is 0.1999 BTC. Failed attempts do not change confirmed state.
- Channel payments preserve total value; closing never increments payment count. Delayed output spending requires clock progression and explicit confirmation. A penalty requires an active observer and explicit timely confirmation. Funding, commitment and penalty/sweep are counted separately.
- Route attempts can fail for directional liquidity or an offline fixture, then retry. Failure delivers/charges zero; success delivers the exact invoice and sender funds fees on top. The 10,199-msat vector remains exact.
- Enhanced controls work by keyboard, explanatory state is text-accessible, and critical pages fit 320px. New state transitions have no automatic animation.

Button actions labelled “confirm” assume inclusion, not transaction construction or actual mining. The 144-block delay and route liquidity fixtures are illustrative. The decoder still does not verify ECDSA, full mandatory/duplicate-feature rules, expiry/payability or intended-recipient identity. Sphinx is not a full TLV or production packet validator. Compact-target helpers do not enforce network-specific expected difficulty or powLimit.
